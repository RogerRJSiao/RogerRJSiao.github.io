Financial RAG
Ollamallama-3-taiwan-8bbge-m3ChromaDBpdfplumberFastAPIDocker
PDF 法說會 / 10-K HTML→表格解析 + metadata→bge-m3 向量化→ChromaDB 檢索→術語對照→繁中回答 + 引用
痛點
美光、南亞科、華邦電的財報都是英文，中文術語和英文欄名對不上；美股與台股財年差一季，人工對照容易拿錯期別；通用 LLM 會編造數字，財報也不適合上傳外部服務。
做法
  • 完全在本機執行的 RAG：解析 PDF 與 10-K 表格，處理多層表頭、假表格、頁尾雜訊。
  • 依公司、財年、財季、報表建立 metadata 過濾，「最新一季」由程式判斷，不靠語意猜。
  • 用財會、半導體中英詞彙表橋接提問與英文欄名；引用來源由系統產生，不交給 LLM 抄寫。
  • FastAPI 封裝成服務，Docker 容器化部署，GPU 推論沿用主機 Ollama。

交通事故嚴重程度預測與高風險情境分析

Traffic Accident ML
Python 3.12pandasscikit-learnjoblibconda
年度 zip→解壓 / 合併 / 清洗（sha256 紀錄）→分層切分 + 欠採樣→Logistic 迴歸→evaluate→promote 登錄版本
痛點
政府公開資料逐年分檔發布，每列是一位當事者而非一件事故；死亡事故（A1）只占約 0.5%，全部猜「受傷」就有 99.5% 準確率。
做法
  • 三支程式處理資料，以 sha256 記錄狀態避免重複處理，並用列數等式驗證清洗沒有遺漏。
  • Logistic 迴歸換算勝算比，直接回答「哪些情境讓死亡事故的勝算變高」。
  • 評估改看 PR-AUC、recall、F2；切點由 validate 決定，test 只在版本定案後用一次。

GitHub / GitLab 內容讀取工具

my_git_mcp
MCP (FastMCP)FlaskhttpxBeautifulSoupGitLab API v4
貼上連結→主機白名單檢查→GitHub REST / GitLab API→統一格式摘要卡片
痛點
公司自架的 GitLab 在內網、需要 token，一般工具讀不到；issue / MR 的狀態、標籤、指派人散落各處，GitHub 和 GitLab 的欄位也不同。
做法
  • 自建 MCP server，讓 Claude 在對話中直接讀取 Git 平台網頁與原始檔。
  • Flask 網頁呼叫官方 API，把 PR 與 MR 整理成同一種摘要格式。
  • 主機白名單防範 SSRF，token 一律由環境變數讀取，支援多台自架 GitLab。
2 種入口MCP 對話工具、Flask 網頁

台鐵時刻表查詢與山海線搭乘規劃

n8n Railway Planner
n8nDockerJavaScriptLuxonHTTP 爬蟲
4 欄表單→3 站時刻表並聯爬取→Merge 同步→JS 解析與比對→直達 / 轉乘 2 份 CSV
痛點
台鐵官網的轉乘查詢只列出部分媒合班次，結果無法下載，表單多達 10 個欄位；山海線列車在途中還會改變順逆行方向。
做法
  • n8n 以 Docker 地端部署，3 個 HTTP 節點並聯爬取，用 Merge 等待全部到齊再比對。
  • 發現車站編號無法判斷山海線方向，改為自建「行車方向參照表」。
  • 凌晨班次改寫為 24:xx，確保跨午夜排序正確。

專案進度填寫提醒與備份自動化

Power Automate Flow

每日排程→讀取期限表→到期前 1–2 日寄提醒→到期日備份並押日期→撞名改發 Teams 通知
痛點
部門進度表靠人工提醒，容易遺漏；檔案持續被覆寫，沒有手動另存就無法回溯各期內容。
做法
  • 雲端 Flow 每日讀取 SharePoint 上的期限清單，提醒信附上檔案連結與填報規範。
  • 到期日自動複製進度檔；同名檔案已存在時跳過，改以 Teams 私訊通知。
  • 整理 7 個平台限制與繞道方式，例如日期字串需以 tick() 轉數值比較。

LabVIEW × C 語言條碼辨識

LabC-Vision
LabVIEW 32-bitC / DLLzbarstb_imageCMake + Ninja
LabVIEW 選圖與條碼種類→CLFN 呼叫 DLL→detect 解碼→validate 驗證→HandleError.vi 顯示訊息
痛點
產線檢測的判斷邏輯寫在 LabVIEW 方塊圖裡，難閱讀、難做單元測試，不同產線還要各複製一份；操作人員只看得到數字錯誤碼。
做法
  • 判斷邏輯移到 C，編成 32 位元 DLL；LabVIEW 只負責畫面與呼叫。
  • 讀檔偵測與編碼驗證分兩階段回報，操作人員能看出問題出在哪一段。
  • 錯誤碼依模組分段（-8000 到 -8900），訊息對照表只有一份。
4 種條碼EAN-8 / 13、UPC-A、手機條碼載具
1 個指令CMake 建置全部模組並跑單元測試

三角與非三角合併報表 v3.1

Power BI DirectQuery
Power BIPower Query MPostgreSQLCHANGELOG
年月 / 公司別參數→組成 SQL WHERE→資料庫端篩選→full 47 欄 / finance 27 欄
痛點
財務報表的 SQL 沒帶篩選條件，每次重新整理都撈回全部年月、全部子公司，最後出現 57014 statement timeout，報表更新失敗。
做法
  • 把篩選參數組成 WHERE 子句下推到資料庫，讓索引在源頭先篩。
  • 依部門需求分出完整版與財務版，未用欄位以註解保留、可隨時復原。
  • 制定 v{主}.{次}_{模式}.pbix 命名規則與共用 CHANGELOG。
